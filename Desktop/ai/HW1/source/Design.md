# Code Agent 设计文档

## 1. 设计目标

实现一个**代码生成智能体**：用户用自然语言描述需求，Agent 自主编写 Python 代码、执行验证、发现错误后自我修正，最终将可运行的代码保存为文件并给出结果总结。

核心设计遵循 **ReAct（Reasoning + Acting）模式**：模型在每一步先"想"（推理），再"做"（调用工具），观察工具返回后继续推理，直到达成目标。

## 3. Agent 循环详解

### 3.1 循环流程

每一轮执行以下步骤：

1. **组装消息**：将系统提示词 + 对话历史 + 工具定义发给 LLM
2. **LLM 推理**：LLM 决定下一步动作——要么调用工具，要么给出最终文本回复
3. **工具执行**：如果 LLM 选择调用工具，Agent 在本地执行工具，将返回结果作为 `role: "tool"` 消息追加到历史
4. **继续循环**：带着工具结果再次调用 LLM，LLM 根据结果决定是继续调用工具还是输出答案
5. **终止条件**：
   - LLM 不再调用工具（产出最终文本）→ 正常结束
   - 达到 `max_turns`（默认10轮）→ 强制终止并提示

### 3.2 消息格式

消息历史遵循 OpenAI Chat Completions 格式：

```python
[
    {"role": "system", "content": "你是一个代码生成智能体..."},
    {"role": "user", "content": "写一个快速排序"},
    {"role": "assistant", "tool_calls": [...]},
    {"role": "tool", "tool_call_id": "call_xxx", "content": "执行成功..."},
    {"role": "assistant", "content": "代码已完成..."}
]
```

## 4. 工具设计

### 4.1 工具列表

| 工具名 | 功能 | 参数 |
|--------|------|------|
| `execute_python` | 执行 Python 代码 | `code: str` |
| `write_file` | 保存文件到 output/ | `filename: str`, `content: str` |
| `read_file` | 读取 output/ 下文件 | `filename: str` |

### 4.2 execute_python 设计要点

- **隔离执行**：使用 `subprocess` 启动独立 Python 进程，崩溃不影响主程序
- **超时保护**：默认 15 秒超时，防止死循环
- **输出捕获**：分别捕获 stdout 和 stderr，格式化后回传给 LLM
- **错误透明**：执行失败时错误信息原样返回，LLM 能看到 traceback 并自我修正

### 4.3 write_file / read_file 安全设计

- **路径白名单**：所有文件操作限定在 `output/` 目录
- **禁止路径穿越**：拒绝包含 `/`、`\` 或绝对路径的文件名
- **自动建目录**：`output/` 不存在时自动创建

## 5. 错误处理策略

| 异常场景 | 处理方式 |
|---------|---------|
| LLM API 网络错误/限流 | 指数退避重试（1s→2s→4s），最多3次 |
| LLM 返回非法 JSON 参数 | 降级为空字典，工具调用返回错误提示 |
| 代码执行超时 | 返回超时提示，LLM 据此优化代码 |
| 代码运行报错 | traceback 原样回传，LLM 自动修复重试 |
| 工具名称不存在 | 返回"未知工具"错误信息 |
| 对话轮数超限 | 返回终止提示，防止无限循环 |

## 6. 记忆机制

- **全量消息历史**：每轮对话的 system/user/assistant/tool 消息全部保留
- **多轮上下文**：Agent 能记住之前写过的代码和执行结果
- **手动清空**：用户输入 `clear` 可重置对话（保留 system 提示词）
- **无窗口截断**：当前实现保留完整历史，适合短任务场景；长任务可扩展滑窗策略

## 7. 扩展方向

- 添加 Web 界面（Gradio / Streamlit）
- 支持更多工具：网络搜索、Git 操作、数据库查询
- 添加代码文件的增量编辑能力（read → modify → write）
- 长对话场景的历史摘要压缩
- 流式输出（SSE）提升交互体验
